PDK Technology & Coverage

The PDK compiler is the process-portability boundary. The same problem setup must handle a 350 nm mature-planar CMOS, a BCD power process, a FinFET predictive node, and a sparse academic PDK by changing the compiled technology model T, not by changing the contract. It is not enough to say a PDK has layers, tracks, vias, and DRC rules — the constraints layer must know which rule classes are enforceable for the requested confidence level.

The compiled technology model

T = (U, L, D, M, V, R, X, C, A, Q)
SectionDefines
Uunits, manufacturing grid, row/site/fin lattice, route tracks, legal phases, coordinate frames.
Llayer roles: active, poly, contact, local interconnect, metals, vias, cuts, wells, implants, markers, passivation, pads, RDL, backside, keepout.
Ddevices, terminal order, PCell parameters, folding, segmentation, dummies, taps, guard rings, wells, bulk/substrate behavior, LVS mapping.
Mmetal/via/cut/color predicates: width, spacing, enclosure, PRL, EOL, notch, min-area, max-width, density, slotting, antenna, DFM.
Vvoltage, current, EM, IR, reliability, latch-up, ESD, isolation, domain-crossing predicates.
Rroute access, pin layers, via stacks, preferred directions, unidirectional restrictions, over-device routing, terminal-access rules.
XPEX, coupling, RC corners, via resistance, shielding, EM, noise, LDE, thermal models.
Ccoloring, multipatterning, EUV, SADP/SAQP, cut masks, decomposition constraints.
Abindings from internal analysis engines and external signoff decks to rule IDs.
Qthe coverage inventory — the universally-required section.
This is a target contract, not today's schema. A present-day PDK schema typically has layers, tracks, vias, simple device rules, and basic DRC rules. Color, density, fill, CMP, lithography, EM/IR/LDE/noise models, external deck IDs, and manual-review coverage must be added as explicit compiler coverage classes or overlays — not assumed.

The coverage inventory and the MCMM key

Industrial signoff is multi-corner, multi-mode (MCMM): a mode fixes clocks, supplies, and active constraints, while a corner fixes a process/voltage/temperature library and extraction view. A rule, model, or electrical bound can be satisfied in one corner and violated in another, and a coverage cell can be Coded for one deck option and Missing for another. Collapsing these views into a single boolean produces the canonical MCMM error — reporting a layout “clean” because the worst view was never evaluated.

The coverage key is therefore six-dimensional:

(rule_id, device_or_layer_scope, corner, mode, deck_id, host_template_id)

Conflict detection runs at the granularity of that key. Normalization groups raw coverage entries by the full key (cost O(r log r)) and, when entries that share a key disagree, collapses the group into a single Contradictory cell whose notes record the disagreeing corner/mode/deck views. That Contradictory cell is the representation of a cross-corner conflict.

Merging required views — the conservative meet

When one obligation depends on a rule across several required MCMM views, the views are merged by the lattice meet of Coverage. The merged cell is Coded only if every required view is Coded; otherwise it is the worst (lowest-information) view. This is the algebraic statement of “passes at TT, untested at SS resolves to the weaker value, not the optimistic one”: 

info:  Coded 8 > Partial 7 > Approximate 6 > RecommendedOnly 5
     > ExternalOnly 4 > ManualReview 3 > Unsupported 2 > Missing 1
     > Contradictory 0

meet(a, b) = the value with the lower info level
merge_required(views) = fold meet over views        // Coded iff all Coded

Two distinct cross-corner situations must not be conflated:

  1. Coverage disagreement — the same rule is Coded at one (corner, mode, deck) and Missing/Approximate at another. The merged cell is Coded only if every required view is; otherwise the dependent obligation cannot reach Gate 0 universally and is reported per-view.
  2. Electrical-bound disagreement — a bounded metric (PEX coupling, IR drop, EM margin) is inside budget at the typical corner and outside at the worst. This is not a coverage gap; it is a Gate-6 failure scoped to the failing corner, attributed to the specific (metric, corner, mode) view.
Conservative acceptance. A result is signoff_quality only if every required corner/mode/deck view passes its hard gates and stays inside its bounded budgets. A layout that passes the typical view but fails a required worst view is reported signoff_ready_at(view) for the passing views and as a bounded/coverage failure keyed to the failing view — never as universally signoff-ready. “Passes at TT, untested at SS/FF” becomes an explicit, certificate-visible state instead of an accidental pass.

Process-node coverage

The same contract spans process families by changing T. What changes is the rule set each family forces into the inventory:

Process familyRequired constraint treatment
Mature planar CMOS (350–130 nm)rich device/well/tap/guard rules, many analog primitives, flexible routing, manual-review rules, RF/passive variants, open-PDK verification gaps.
BCD / HV / automotive / powervoltage-dependent spacing, isolation, latch-up, guard rings, ESD, thick metals, current density, thermal, safe operating domains.
RF / BiCMOSsubstrate coupling, inductor/transformer keepouts, transmission-line behavior, shield topology, passives, device-specific extraction, HBT/RF/HV device classes.
Scaled planar (90–28 nm)tighter DRC, density/fill, antenna, CMP, OPC/lithography effects, local interconnect, stricter pin access.
FinFET / 7 nm-class predictivediscrete fin/site choices, unidirectional routing, cut masks, color, MOL/BEOL restrictions, SADP/SAQP/EUV assumptions.
GAA / CFET / backside / 3D / RDLstack orientation, backside/BEOL separation, thermal/reliability coupling, new layer classes, package-facing constraints.
Sparse research PDKpartial coverage, approximate extraction, synthetic checks, mandatory degraded-confidence status.
Contradictory / missing PDKfail early with coverage/core diagnostics, not a guessed signoff result.
Cross-corner / MCMM conflictrule/model coverage, deck behavior, or electrical bounds disagree across PVT, mode, voltage domain, host template, or extraction corner.

The important rule throughout: unsupported coverage is not success. A layout can be internally DRC-clean under coded min-width and min-spacing rules while still not be signoff-quality because notch, antenna, HV, density, color, or manual-review requirements are absent. Coverage must be tracked per corner and mode; a layout clean for one RC corner or deck option but uncertified for another cannot be reported as universally signoff-ready.

Why coverage is an abstract domain

Coverage accounting makes a safety claim — “no required rule is silently treated as present when it is not” — and abstract interpretation is the theory of making such claims sound by construction. An abstract analysis must over-approximate the concrete one: it may lose precision but must never miss a concrete behavior, so a sound analysis has no false negatives. The coverage lattice (Coded … Missing / Contradictory) is the abstract domain, and the merge above is its meet. The soundness obligation Philis inherits is the conservative direction of every uncertain join: when two views disagree or a value is unknown, the merged coverage moves toward Missing/Contradictory, never toward Coded. That is the formal reason a layout is reported signoff_ready_internal rather than signoff_quality whenever any required cell is below Coded — over-approximating risk (never under-approximating it) is the abstract-interpretation soundness condition that keeps the certificate from certifying a gap it failed to model.
