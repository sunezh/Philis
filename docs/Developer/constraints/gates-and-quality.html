Gates & Quality

Acceptance is a strict lexicographic order, not a weighted sum. A hard vector dominates a bounded electrical vector, which dominates a soft ranking vector. This is the single most load-bearing decision in the whole subsystem: it is what makes “DRC=0 and LVS=true” un-buyable by any amount of soft quality.

The formal problem setup

The constraint compiler input is a bundle:

I_c = (T_raw, S, H, G, M, O, U, A, B, E_prev)
SymbolMeaning
T_rawthe foundry / open / predictive / overlay PDK bundle.
S = (D, N, ports)the schematic graph of devices, nets, and terminals.
Hthe hierarchy graph, including repeated subcircuits and preserved boundaries.
Gthe primitive source catalog: generated devices, imported cells, black boxes, fixed macros, PCells, terminal maps.
Mthe host layout contract: fixed tile, padframe, wrapper, rail map, fixed pins, seal ring, reserved resources, export rules.
Ofixed geometry, obstacles, prior routes, keepouts, blockages, wells, guard structures, substrate domains, external macros.
Uexplicit user constraints and waivers.
Aanalysis oracles and their declared capabilities (internal DRC/LVS/PEX/EM/ERC, external hooks, deck IDs, corner models, manual-review policies).
Bthe budget vector: runtime, memory, iterations, allowed degraded confidence, electrical bounds, corners, repair limits.
E_prevprevious evidence from placement, routing, or analysis runs.

The compiler output is:

O_c = (T, F, I, P_place, P_route, P_analysis, K, Q, Cert)

where T is the compiled technology model, F the canonical fact graph, I the IntentGraph, the three P_* the consumer projections, K the contradiction/ambiguity/infeasibility/repair-core set, Q the lexicographic quality & coverage vector, and Cert the replayable certificate.

The lexicographic objective hierarchy

Acceptance is staged through eight ranks. Every rank must pass before the next is even consulted; the order also governs which violation is blamed first. 

Gate 0  required PDK / deck / host / model coverage            ← hard
Gate 1  well-formed schematic, hierarchy, terminals, prim maps ← hard
Gate 2  no contradictory hard intent                           ← hard
Gate 3  placement-owned DRC and LVS-readiness obligations      ← hard
Gate 4  terminal access, routing feasibility, route-intent     ← hard
Gate 5  final DRC = 0 and LVS = true                           ← hard
Gate 6  PEX, IR, EM, noise, antenna, LDE budgets inside bounds ← bounded
Rank 7  minimize residual PEX, mismatch, area, wirelength,
        vias, density stress, runtime                          ← soft

Gate 0 is intentionally first: a layout cannot be called signoff-quality if the PDK or analysis deck lacks required rule coverage. Gate 5 is the explicit system-level acceptance target — the constraints layer tracks the obligation and evidence status while analysis and trusted external decks provide the final proof. Gate 6 captures the parasitic-quality goal: minimize PEX only after DRC and LVS are feasible, and enforce explicit bounds before any soft ranking.

The three quality vectors

Let x be a complete or partial layout state. The problem defines H_i(x) = 0 for every hard violation count, B_j(x) ≤ bound_j for every bounded metric, and S_k(x) minimized only after all H_i and B_j pass. 

hard(x) = (
  missing_required_coverage,
  malformed_input,
  contradictory_hard_intent,
  primitive_or_terminal_LVS_readiness_failures,
  placement_owned_DRC_failures,
  missing_terminal_access,
  routing_required_connectivity_failures,
  final_DRC_violations,
  final_LVS_mismatches)

bounded(x) = (
  PEX_resistance_bound_excess,
  PEX_ground_cap_bound_excess,
  PEX_coupling_bound_excess,
  matched_group_delta_excess,
  IR_drop_excess,
  EM_margin_deficit,
  crosstalk_or_noise_excess,
  antenna_margin_deficit,
  LDE_or_thermal_bound_excess)

soft(x) = (
  residual_weighted_PEX_damage,
  residual_matching_slack,
  area,
  HPWL_or_route_length,
  via_count,
  density_stress,
  fill_and_DFM_cost,
  runtime,
  repair_iterations)

Candidate x_a is better than x_b iff:

hard(x_a) lexicographically improves hard(x_b),  OR
hard(x_a) = hard(x_b) = 0  AND  bounded(x_a) lex-improves bounded(x_b),  OR
hard and bounded both feasible  AND  soft(x_a) improves soft(x_b)

Why scalarization specifically fails

The lexicographic order is not stylistic; weighted penalties are provably unsound. Suppose a single objective Φ(x) = w_h·hard(x) + w_b·bounded(x) + w_s·soft(x) with positive weights. For any finite w_h, take a DRC-dirty candidate x₁ with one hard violation and a DRC-clean candidate x₂ whose only deficit is a worse soft score. Whenever soft(x₂) − soft(x₁) > w_h / w_s, we get Φ(x₁) < Φ(x₂) — the DRC-dirty layout wins. No finite weights close this hole for all inputs, because the soft metrics (area, wirelength, vias) are unbounded above. The only way to make a hard violation un-buyable is to compare hard counts first and consult soft scores only on ties — which is the lexicographic order, equivalently the unreachable limit w_h/w_s → ∞.

The gate property. A scalar penalty fails the gate property by construction; lexicographic ordering satisfies it by construction. Backends may still use scalar costs within a fixed gate, but the public acceptance relation stays staged and evidence-carrying.

The theory behind the gate

Constraint hierarchies. Borning's constraint-hierarchy theory formalizes over-constrained systems with a distinguished required level H₀ that must hold exactly and weaker preferred levels. Every admissible comparator must respect the hierarchy: if some valuation satisfies all constraints through level k, every solution must. The decisive theorem is that no aggregation across levels lets a weaker level override a stronger one — a constraint at a given strength “completely dominates” any number of weaker ones. Philis's hard ≻ bounded ≻ soft order is a constraint hierarchy with H₀ the hard vector; the comparator is the locally-predicate-better comparator. The gate semantics is a 30-year-old result about why required constraints cannot be priced, not a Philis invention.

Semiring / valued CSP. The quality algebra is a c-semiring (A, ⊕, ⊗, 0, 1): ⊗ combines several constraints' values and ⊕ chooses among alternatives. Two Philis mechanisms are c-semiring operations: the coverage meet is a conservative ⊗ that yields the worst view, and the quality comparator is a partial order (idempotence of ⊕ guarantees it is well-defined) so genuinely incomparable candidates are reported as incomparable rather than forced into a false ranking. The framework also proves local-consistency propagation is sound under any c-semiring — the licence to run cheap local conflict detection before invoking the exact solver.

The realized placement gates

The system-level gates above are split by ownership across stages. The placement-owned subset is already encoded in the public API as AcceptanceGate (crates/api/src/core.rs), with the realized evaluation order in ACCEPTANCE_GATE_ORDER: 

TechnologyCoverage → LocalDrc → DeviceEquivalence
  → TerminalAccess → Routability → IntentSatisfaction

The realized order deliberately differs from the design-rationale order: LocalDrc runs before DeviceEquivalence (it is the cheapest high-yield rejector) and IntentSatisfaction runs last (it is repairable before legalization). Only LocalDrc and IntentSatisfaction are is_repairable(); the rest are terminal — legalization cannot conjure a missing rule deck, device generator, access set, or channel capacity, so their failure produces a conflict core. Each gate yields a GateStatus of Pass / Degraded / Fail, and a result is signoff-quality only when every gate is Pass on coded evidence (PlacementCertificate::is_signoff_quality).

Realized class & coverage subsets. The realized IntentClass (Hard | Bounded | Soft | Unsupported) and CoverageClass (Coded | ExternalOnly | Unsupported) are the subsets of the canonical seven-class ObligationClass and nine-valued Coverage that the engine encodes today. They are designed to widen toward the canonical enums without changing the gate semantics — the lexicographic order is invariant to how finely the classes are subdivided.
