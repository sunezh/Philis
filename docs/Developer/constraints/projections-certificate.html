Projections, Evidence & Certificate

This page covers the back half of the pipeline: how the IntentGraph becomes typed consumer obligations (projection), how conflicts are resolved without losing provenance (reconciliation), how signoff evidence flows back without thrashing (the evidence loop), how the typed problem is lowered to backends (the solver stack), and what the system ultimately returns (the certificate). Three of the four formal invariants live here.

Projection — a view, not a translation

Projection is a deterministic query over the canonical graph that selects the obligations relevant to one consumer and reshapes them into that consumer's schema. It is not a best-effort rewrite into the consumer's native vocabulary — which would silently lose whatever does not fit. 

Project_place(I)    → obligations over primitive choices, transforms,
                      terminals, host objects, access witnesses, local checks
Project_route(I)    → obligations over nets, terminals, access choices, routes,
                      shields, matching, power, repair, and PEX budgets
Project_analysis(I) → obligations over rule IDs, expected evidence, corners,
                      snapshots, external decks, and unsupported rules

Invariant 1 — projection soundness (no add, no silent drop)

For every consumer s ∈ {place, route, analysis}, let Oblig_s(I) be the obligations whose consumer mask includes s. Then a projection must satisfy: 

Project_s(I).expressed  ∪  Project_s(I).skipped  =  Oblig_s(I)   (partition)
Project_s(I).expressed  ∩  Project_s(I).skipped  =  ∅
∀ p ∈ expressed ∪ skipped :  p.id ∈ ids(I)                      (resolves back)

A projection may not invent an obligation absent from I (every projected ID resolves back into the graph), and it may not drop a consumer-relevant obligation without recording it in skipped with a reason. The absence of a skip is a positive, replayable claim that the obligation was honored.

In compiler terms this is translation validation, not a verified compiler. Philis does not prove once and for all that projection preserves semantics; instead every individual projection run emits a witness whose check is cheap and replayable — the expressed/skipped partition plus the canonical-ID links is the simulation relation made concrete. The projector may use any internal strategy and change between releases, yet each run still carries a self-contained certificate that it neither invented nor silently dropped intent.

The inexpressibility contract

When consumer s cannot represent an obligation c in its native model, it must do all of the following, in order, and may do none of them silently:

  1. Emit a linked skip. Append a ProjectedConstraintSkip { constraint_id: c.id, reason } to the consumer's skipped/unsupported list. The constraint_id is c's canonical ID; the reason is a typed category (inexpressible, out-of-scope, coverage-gap, capability-version-mismatch), not free prose.
  2. Never approximate a hard obligation into a soft one. If c is Hard/Joint and the consumer cannot express it, the skip is itself a hard-gate input — the obligation surfaces in the relevant hard count and fails the lexicographic gate rather than vanishing.
  3. Downgrade only with authority. A consumer may report a downgraded status (e.g. heuristic terminal access in place of a proven witness) only when policy permits, recorded as DegradedConfidence evidence keyed to c.id, which forces the final claim to signoff_ready, not signoff_quality.
  4. Round-trip through evidence. The skip/downgrade enters E_prev so the next compile can attempt repair, choose a fallback projection, or escalate to a contradiction core if no consumer can ever honor c.

The contract is symmetric: the analysis consumer that lacks an internal check for a rule does not drop the rule — it emits an UnsupportedRequirement or ExternalDeckRequirement linked to the rule's obligation ID, the analysis-side form of the same skip.

Projection report types

The three projections carry the consumer-shaped obligation lists:

PlacementConstraintProjection {
    primitive_obligations, geometry_obligations, matching_obligations,
    host_obligations, terminal_access_requirements, routability_requirements,
    pex_envelopes, skipped }

RoutingConstraintProjection {
    net_classes, terminal_access, connectivity, shields_and_guards, matching,
    power_and_domain, pex_ir_em_noise_bounds, repair_groups, skipped }

AnalysisObligationProjection {
    drc_rules, lvs_expectations, pex_corners, em_ir_noise, external_decks,
    manual_review, unsupported }

Projections are incrementally maintained views

Framing a projection as a materialized view (rather than a one-shot translation) is what licenses the partition invariant — a view adds no tuple absent from its source and is recomputable at any time — and what makes incremental recompilation tractable. The IntentGraph is rebuilt on every edit, but recomputing everything from scratch on each keystroke is wasteful. The discipline is incremental view maintenance (DBSP-style): the obligation set is a weighted multiset (a Z-set) keyed by content-addressed ID; a re-detect of an unchanged obligation contributes a +1 that cancels the prior state's +1 (zero net change, no downstream work — “unchanged” is decidable by ID equality, for free, because of content addressing); and a genuine edit contributes a small delta that flows through the incrementalized projection to update only the affected entries and certificate sections. Two Philis properties make this applicable rather than merely analogous: determinism (the same input change yields the same output change) and content addressing (deltas are computed by ID set difference, not structural diffing).

Reconciliation — waivers and cores

Invariant 2 — waiver∘authority composition

Waivers compose with authority as a guarded annotation, never a deletion. Let rank(·) be the precedence order. A waiver w over obligation c is admissible iff: 

admissible(w, c)  ⇔  rank(authority(w)) ≥ rank(required_authority(c))

apply(w, c) = c with waiver := Some(w)   if admissible(w, c)
            = c with waiver := None      otherwise (+ diagnostic)

Composition is idempotent and order-independent: applying an admissible waiver twice equals once, and admissible waivers can be applied in any order with the same result, because admissibility depends only on the static (authority, required_authority) pair. An inadmissible waiver is rejected (the obligation snaps back to enforced) and emits a diagnostic — never silently honored. Because waived obligations stay in the graph (only the waiver field is set), the certificate can still report what was waived, by whom, and under which authority — mandatory for any signoff claim resting on a waiver.

This is exactly the discipline an assumption-based truth maintenance system (ATMS) arrived at: a waiver is an assumption with an authority rank; the obligation's retained waiver field plus provenance edges are its label; and a contradiction core is a nogood. Keeping waived obligations in the graph keeps the ATMS label intact, which is what lets the certificate answer “on which assumptions does this signoff claim rest?” — the question an unrecorded hard delete makes unanswerable.

Invariant 3 — contradiction-core minimality

Cores carry an explicit minimality tag naming the guarantee they actually provide, rather than overclaiming a globally minimal unsatisfiable subset:

TagGuaranteeProduced by
singletona single self-contradictory obligation (e.g. a hard obligation whose coverage is Missing/Contradictory). Trivially minimal.structural (cheap)
pairwisetwo obligations that disagree; removing either removes the contradiction. Minimal w.r.t. the conflict relation.structural (cheap)
groupwise / victimwisegroup-preserving / authority-driven sacrifices.structural (cheap)
set-minimal-preferreda single preferred MUS under an authority ordering.QuickXplain (exact)
set-minimal-enumeratedone of several independent MUSes.MARCO (exact)

Reconciliation-time cores advertise the cheap, structural guarantee so the certificate never claims more minimality than was proven; deck-level set-minimality is reserved for the exact-solver path and tagged with the algorithm that certifies it. Each core also content-addresses its identity (a hash of the sorted member-ID list plus a reason tag), so “the same infeasible case always produces the same conflict core” is a checkable invariant.

MUS, MCS, MaxSAT, and hitting-set duality

Over an unsatisfiable obligation set F, the certificate names which object it reports:

  • MUS — a Minimal Unsatisfiable Subset: an infeasible S ⊆ F whose every strict subset is feasible. A minimal reason: drop any member and the contradiction vanishes.
  • MCS — a Minimal Correction Set: a C ⊆ F such that F \ C is feasible and no strict subset is. A minimal repair: relax/waive exactly these and feasibility returns.
  • MaxSAT — satisfy as many (weighted) obligations as possible; its complement is a minimum-weight MCS, the cost-optimal member of the MCS family. This is why the bounded/soft tiers can be lowered to weighted partial MaxSAT once the hard tier is fixed.

Hitting-set duality ties them together: a subset is a MUS iff it is a minimal hitting set of all MCSes, and dually. So a repair and an explanation are two readings of one structure — the conflict core and the suggested relaxation come from one enumeration, not two. The certificate tags each core with both its minimality kind and the algorithm that produced it, so a reader knows whether they hold a single preferred reason or an exhaustive set, and whether the paired relaxation is cost-optimal (MaxSAT) or merely minimal (MCS).

The evidence & repair loop

Invariant 4 — monotonic evidence ingestion (no thrashing)

Evidence updates the graph monotonically. Each ingested report can only tighten the feasibility picture for a given key — it adds a result, refines a coverage cell, or opens a repair obligation, but never silently overwrites a prior failing result with a passing one without recording the transition. The ingestion key is: 

(constraint_id, domain, subject_key, corner, mode, deck_id)

Results accumulate as an append-only ledger keyed by that tuple. A later “pass” after an earlier “fail” for the same key is recorded as a repair transition with both endpoints retained, not as an erasure. This prevents the classic repair-loop pathology where a constraint flips pass/fail/pass and the solver oscillates: because the ledger is append-only and keyed, the lexicographic comparator sees a strictly non-increasing hard vector across accepted repair steps, so a repair that does not reduce the hard (then bounded) vector is rejected. Termination reduces to the well-foundedness of the lexicographic order on a bounded-dimension non-negative integer vector.

The solver stack

Solving is a stack of specialized backends, not one global scalar optimizer. A single generic local search cannot prove infeasibility (failing to find a solution is indistinguishable from a timeout) and cannot emit an unsat core; forcing finite hard decisions through a continuous optimizer either rounds illegally or stalls.

LayerRole
Exact feasibilitySMT / CP-SAT / MILP / MaxSAT for finite hard decisions: primitive variants, symmetry membership, order, common-centroid unit assignment, host pin binding, voltage-domain separation, route-group membership, unsupported-rule policy.
Graph algorithmsunion-find, bipartite matching, graph isomorphism, min-cut, flow, coloring, hypergraph partitioning where structure is graph-native. Joint obligations are encoded as global constraints with matching-based filtering (prune to generalized arc consistency in one pass), preserving the group as an atomic unit.
Analytical relaxationscontinuous proxies for area, density, congestion, PEX, thermal, LDE, soft parasitic ranking — after hard gates are fixed.
Heuristic repairsearch and repair for local violations, storing learned penalties and nogoods as evidence tied to canonical IDs.

The public lowering surface carries a staged or vector objective before any backend-specific lowering, plus a closed set of backend artifact classes: 

LexicographicObjective { hard: Vec<HardGate>, bounded: Vec<BoundedMetric>, soft: Vec<SoftMetric> }

BackendArtifact = ProofLog | UnsatCore | CorrectionSet
                | FeasibleModel | ModelInvalid | Unknown | HeuristicTrace
Budget-gated explanation. The exact MUS/MCS pass is the only super-polynomial component and is bounded by the budget vector. If the cap is hit, the solver returns Unknown with a partial core rather than reporting infeasibility — a timeout is never reported as proven-infeasible or signoff-ready.

The constraint certificate

The output of the system is a certificate, not merely a list of constraints. It is the replayable record a third party uses to re-check every invariant. It should include:

  • canonical input hashes for schematic, hierarchy, PDK, host template, user constraints, and fixed geometry;
  • the PDK / deck / model coverage inventory with stable rule IDs and the hash family used for identity;
  • the normalized IntentGraph and the three projection reports (expressed + skipped/downgraded);
  • applied, skipped, downgraded, unsupported, external-only, and manual-review obligations;
  • hard-vector and bounded-vector status;
  • DRC, LVS, PEX, EM, ERC, antenna, density, color, and manual-review evidence requirements;
  • solver transcripts sufficient to reproduce hard decisions or identify unsat cores — proof logs, unsat cores, correction sets, feasible models, invalid-model reports, unknown statuses, heuristic traces;
  • the deterministic seed and tie-break policy;
  • repair history and learned nogoods;
  • degraded-confidence flags and user waivers.

The realized API already ships a stage-scoped instance of this idea: the PlacementCertificate in crates/api/src/core.rs carries the acceptance-gate verdicts, the degraded-confidence causes, the solver path, the replay seed, and a RouterHandoffWitness. Its ::stub() form is the honest placeholder — every gate Degraded with an “engine stub” cause — so the surface never claims a signoff it has not proven. A PlacementCertificate proves only facts owned by placement and checked by declared oracles; it is not a foundry-signoff substitute. Final DRC=0 and LVS=true belong to verification, to which the constraints layer projects analysis obligations and from which it ingests counterexample-carrying evidence — a closed loop with the canonical constraint_id as the only shared key.

Case taxonomy

A paper-quality formulation must cover all relevant cases, not only easy current-mirror or differential-pair examples. The solver/verification state axis in particular must distinguish six outcomes that a naive system would collapse:

StateRequired behavior
Cleanall gates pass on coded evidence → signoff-quality.
Repairableevidence opens a repair obligation that strictly improves the hard/bounded vector.
Degraded confidencepasses coded gates but a required rule/model/deck is external/approximate/missing → signoff-ready, not signoff-quality.
Proven infeasiblereturns a stable conflict core, never a guessed layout.
Timeout / unprovenreturns Unknown + partial core — never reported as infeasible or signoff-ready.
Cross-corner conflictidentifies the (rule, corner, mode, deck, host-template) key that prevents universal acceptance.

Worked example

A differential input pair with a current-mirror load illustrates the contract. The compiler does not stop after detecting symmetry: it emits placement obligations (symmetry axis, same template, common-source alignment), routing obligations (matched drains, shielded high-Z nodes, power trunk), and analysis evidence requirements (LVS terminal map, PEX delta bound, DRC rules). If post-route PEX violates the pair delta, the repair obligation is attached to the matched group and cannot be solved by perturbing one route independently unless the graph explicitly allows that degradation.

A second example — a fixed-template LDO or bandgap in an open-source PDK where antenna, density/fill, or HV isolation rules are external-only or manual-review — still emits placement and routing obligations, but the certificate must say: 

Coverage(rule=antenna.*, corner=all, deck=open)   = ExternalOnly
Coverage(rule=density_fill.*, host=template_A)    = ManualReview
TerminalAccess(pin=VOUT, source=heuristic)        = DegradedConfidence
FinalClaim     = signoff_ready_internal, not signoff_quality
RequiredEvidence = external antenna deck + manual fill review + access witness

If the user requested signoff-quality output, this state is incomplete, not successful. If they requested exploratory output, it is acceptable only with explicit degraded-confidence flags and replayable evidence requirements.
