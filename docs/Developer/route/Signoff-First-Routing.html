The Signoff-First Routing Problem

This page is the formal specification the Philis router is built against. It is the implementable form of papers/router/spout-router-problem-setup.md, with every symbol tied to a Philis type where one exists (see API Mapping & Stubs).

1. Formal problem setup

The router input is the tuple

I = (T, S, P, C, O, B)
  • T — the compiled technology model.
  • S = (D, N, ports) — the schematic graph of devices, nets, and terminals.
  • P — the placement with instance transforms and pin geometry.
  • C — explicit and inferred analog routing constraints.
  • O — existing obstacles, fixed shapes, keepouts, blockages, guard structures, wells, reserved resources.
  • B — the budget vector: runtime, iterations, memory, optional electrical bounds.

Before search, C is compiled into an IntentGraph: a typed artifact of hierarchy boundaries, repeated subcircuits, symmetry axes, matched groups, common-centroid arrays, differential pairs, self-symmetric nets, guard-ring closures, shield requirements, substrate-sensitive nets, RF transmission-line classes, high-voltage domains, power-current requirements, and multiport terminal classes. These intents are hard constraints, joint constraints, or bounded objectives — never comments. If intent extraction is ambiguous, the router returns a typed ambiguity diagnosis before search.

The compiled technology model

T = (L, G, V, R, E, X, M)
  • L — the ordered layer stack.
  • G — the legal manufacturing grid and per-layer routing grid.
  • V — the legal via and cut-transition set.
  • R — the set of DRC predicates.
  • E — per-corner extraction models (R, ground C, coupling C, via R, antenna, EM, IR, crosstalk/noise surrogates).
  • X — the connectivity extractor used for LVS.
  • M — process metadata: node family, layer classes, color/pattern domains, density windows, thickness, resistivity, permittivity, corner variants.

The resource graph

The router builds a directed resource graph G_R = (Q, E_R). Each vertex q is a legal point, access patch, via origin, or shape anchor on a layer. Each edge is a realizable segment, via transition, jog, patch, or local access feature — not a bare grid arc. Every edge carries process and extraction attributes: 

attr(e) = (layer, width, enclosure, color, length, R, Cg, Cc_window, rule_mask)

Extraction attributes record their calibration source, process corner, coupling context, whether via resistance is merged or separated, and whether topography/density/fill context affects the estimate. Internal extraction is a calibrated surrogate for signoff extraction, not a substitute for the reference deck; where a reference extractor is available the certificate records the delta to a SPEF-equivalent report.

Decision variables

a[t,k]      = 1 if terminal t uses access candidate k
x[n,e]      = 1 if net n uses routing edge e
v[n,u]      = 1 if net n uses via option u
w[n,e,c]    = 1 if net n uses width/spacing class c on edge e
sh[n,e]     = 1 if edge e is reserved or used as a shield for net n
col[n,e,p]  = 1 if edge e uses pattern/color p
patch[n,p]  = 1 if minimum-area or enclosure patch p is emitted
st[n,e]     = 1 if edge e uses a stitch or decomposition boundary
mask[n,e,p] = 1 if edge e is assigned to mask or cut-mask domain p

Auxiliary continuous/integer variables track parasitic totals, coupling windows, length-match error, density slack, antenna ratio, and EM current density.

2. Feasibility constraints

A. Terminal access

Every required terminal selects at least one legal access candidate:

sum_k a[t,k] = 1   for all required terminals t

A candidate is legal only if it satisfies grid, layer, pin-shape, via-enclosure, cut-spacing, minimum-area, and obstruction predicates. If no candidate exists, the problem fails before global routing and returns the terminal, instance, layer, and violated predicate set.

B. Connectivity — ILP vs. route-state invariant

For each net, selected access candidates must be connected by used edges. The integer multicommodity-flow form is the specification: 

sum_out f[n,t,e] - sum_in f[n,t,e] = demand[n,t,q]
0 <= f[n,t,e] <= x[n,e]

It is not the default runtime. The router picks a mode by size and criticality:

  1. Exact ILP/SMT mode — only for small, decision-dense clips: pin-access selection, via/color/min-area legality, and tightly coupled differential or common-centroid escapes where the net-ordering problem would otherwise corrupt a matched group.
  2. Route-state-invariant mode — the default. Per net, maintain a union-find partition of its used edges and terminals and enforce, incrementally after every commit and rip-up: all selected access candidates of n are in one class, and that class touches no other net's class. This invariant is exactly the connectivity-and-no-short feasibility of the ILP restricted to the committed assignment, so the ILP is solved implicitly and certifiably without enumerating its variables.

Either way, one proof obligation holds: all schematic terminals on a net belong to one extracted connected component unless the schematic explicitly allows multiple. The certificate records which mode certified each net.

C. No-short and resource exclusivity

x[n,e] + x[m,e'] <= 1   for every conflict pair (e,e') with n != m

The conflict relation includes exact overlap, minimum spacing, EOL, parallel-run-length spacing, cut spacing, enclosure, color conflicts, forbidden via stacks, blockage spacing, and process-specific exceptions. Same-net geometry is not automatically free: same-net spacing, notch, hole, self-overlap, min-area, and antenna predicates are still checked through R.

D. PDK rule predicates

R_i(Geometry, Context, T) = true   for every predicate R_i in R

Predicates are callable at three granularities:

  1. Local candidate check for access points and route edges.
  2. Incremental delta check after a commit or rip-up.
  3. Full final check before result acceptance.

The rule oracle supports at least:

  • manufacturing grid; layer allow/deny and preferred direction; min/max width;
  • min spacing with width / PRL / EOL dependencies; same-net spacing and notch;
  • minimum area and area-patch legality; via enclosure, cut size/spacing, via array, stacked-via;
  • density and fill-blocking windows; antenna and diode-repair hooks;
  • color/multipatterning compatibility, cut-mask assignment, stitch count, via decomposability, overlay length, mask balancing;
  • acute angle, hole, self-overlap, polygon topology; DFM/litho predicates (dummy fill, CMP planarity, slotting, post-OPC printability, process-window robustness);
  • high-voltage, guard-ring, well, substrate, and latch-up spacing when the PDK provides them.

E. LVS equivalence

X(Geometry, T) == S   under net and device equivalence

The minimum routing obligation is net connectivity: no opens, no different-net shorts, no layout-only net geometry. For full analog closure the certificate also records whether routing geometry changes device recognition (accidental bridging of diffusion, well taps, guard rings, or local interconnect).

F. Parasitic objective

For each net, incremental extraction estimates

PEX(n) = (R_n, Cg_n, Cc_n, Rvia_n, L_n, EM_n, antenna_n)

and the soft parasitic-damage objective is

Phi_pex = sum_n alpha_n R_n + sum_n beta_n Cg_n + sum_(n,m) gamma_nm Cc_nm
        + sum_n delta_n Rvia_n + sum_g eta_g mismatch_g
        + sum_n theta_n EM_margin_penalty_n + sum_n kappa_n antenna_penalty_n

Weights are not universal constants — they come from circuit intent. For an RF inductor shield coupling may dominate; for a bias net leakage and shielding may dominate; for a digital control net completion and low congestion may dominate.

G. In-loop electrical signoff

The router evaluates three signoff classes during search, not only at the end: geometry legality (DRC), connectivity equivalence (opens, shorts, unintended device/tap/well/guard-ring connectivity), and electrical signoff (corner parasitics, coupling capacitance, crosstalk/noise surrogates, static IR drop for power/ground, current density, antenna, EM margin). These run on every meaningful commit so repair localizes offending geometry before clean routes are disturbed. If a needed corner, calibration file, or model class is unavailable, the result is marked degraded-confidence rather than silently treated as signoff-clean.

Matched groups, common-centroid arrays, and self-symmetric nets are routed jointly. The repair loop preserves symmetry axes, equalizes via count and layer transitions where required, and bounds skew, parasitic imbalance, and coupling asymmetry. An individual net may not be rerouted independently if doing so breaks its group constraint — see the group-preserving invariant.

3. The objective hierarchy

The setup is lexicographic. The four hard levels must each be satisfied in order before any soft objective is compared: 

Level 0: PDK validity and legal terminal access
Level 1: DRC = 0
Level 2: LVS = true
Level 3: all required nets routed
  ── then, inside the feasible region (Pareto / weighted) ──
Soft 1: minimize parasitic damage (Phi_pex)
Soft 2: minimize analog mismatch
Soft 3: reduce wirelength, vias, density stress, runtime

The hard and soft vectors are exactly those on the overview. The hard vector is philis::router::HardVector; the soft tail is the only part that is weight-tunable.

4. The PDK rule compiler

The compiler is the process-portability layer. It maps foundry/open PDK data into typed oracles: a layer/grid/via technology graph, a rule oracle, a PEX/EM oracle, and the terminal-access oracle input. Its output includes stable layer identifiers and classes (diffusion, local interconnect, poly, contact, via, routing metal, thick metal, RDL, well, implant, marker), per-domain grids, tracks and preferred directions, via/array/enclosure/resistance/stacking rules, rule predicates with their dependencies, electrical parameters, DFM/litho surrogates, and external signoff adapters where available.

Rule coverage — the canonical vocabulary

Open and sparse PDKs are not merely lower-confidence; they contain rules that are explicitly not coded, rules caught only by LVS, and rules that must be manually reviewed before tapeout. Each predicate is therefore classified by a canonical coverage enum (philis::router::Coverage): 

Coverage = Coded | Partial | Approximate | ExternalOnly | ManualReview
         | RecommendedOnly | Unsupported | Missing | Contradictory

ExternalOnly carries an evidence domain (e.g. LVS). The certificate reports rule coverage, not just DRC pass/fail, so "internal evidence without required decks" reads as signoff-ready, not signoff-quality.

The four PDK states

From the per-predicate coverage buckets plus structural sanity of layers/tracks/vias, the compiler classifies the whole PDK (philis::router::PdkState):

PDK stateDominant coverage profileRouter behavior
FullSignoffall required classes Coded; no ManualReview/Unsupported gapsUse exact rules and external final signoff.
AbstractCompleterequired classes present, some Partial/ExternalOnlyUse internal predicates; flag signoff confidence as abstract.
SparseResearchUnsupported/ManualReview dominateRoute only under known rules; return degraded-confidence certificate.
ContradictoryOrMissingContradictory/Missing required classes, or broken structureRefuse affected route classes; report unsatisfied PDK fields.

The classifier is deliberately conservative: a single Missing required rule class or structural defect promotes the whole PDK to ContradictoryOrMissing, and any Unsupported/ManualReview rule prevents a FullSignoff claim.

5. Process-node coverage

A process-portable router handles node families by changing the compiled T, not by changing router code. It maintains feature capabilities (color support, voltage domains, RF shields, min-area patching, stacked vias, density repair, antenna repair, external signoff) — never a "SKY130 router" / "ASAP7 router" strategy matrix.

6. The terminal access oracle

Terminal access is a first-class subproblem — a path search cannot repair a missing legal access point. For each terminal the oracle returns a ranked set A_t = { candidate(t,k) }. Each candidate records terminal/instance identity; pin shape, multiport option, or heuristic anchor; layer and legal via stack; on-grid point or legal access patch; a local DRC proof; expected parasitic access cost; symmetry/matching class; role, orientation, access priority, equivalence class; and a confidence level (philis::router::AccessConfidence): 

AccessConfidence = ExactPin | GeneratedPin | InferredPin | HeuristicPin

Candidate ranking is stable and multi-objective:

  1. exact legal pin access before heuristic access;
  2. no-via or fewer-via access before stacked-via access;
  3. lower local DRC margin risk before tighter local margin;
  4. lower parasitic access cost before longer access;
  5. symmetric counterpart availability before isolated candidate quality.

Each generated device exposes a set of multiport terminal candidates with role, orientation, layer stack, access region, equivalence class, and priority. Dot-model pins are a degraded-confidence fallback only: the default analog model represents multiple electrically equivalent access locations, often distributed over different fabrication layers. If placement does not expose orientation or exact pin geometry, the router may create heuristic anchors, but the certificate marks those nets as heuristic-access — not a signoff-quality answer until verified by exact device geometry.

7. Search and repair

The routing loop is conflict-directed, not purely shortest-path:

BuildProblem ─▶ AccessAnalysis ─▶ InitialRoute ─▶ Verify
  Verify ─[DRC=0 ∧ LVS=true ∧ PEX in target]─▶ Accept ─▶ done
  Verify ─[violation / open / short / PEX outlier]─▶ Diagnose
    Diagnose ─[no legal access ∨ unsat hard rules]─▶ Infeasible ─▶ done
    Diagnose ─▶ RipupScope: group-preserving closure scope(V)
      RipupScope ─[budget exhausted]─▶ Timeout: return best verified ─▶ done
      RipupScope ─▶ Reroute: exact-local + negotiated + maze ─▶ Verify

A strong implementation combines three engines (full derivations on the Algorithms page):

  1. Exact local feasibility — SAT/SMT/ILP or exhaustive enumeration for small pin-access, via, color, min-area, and local conflict problems.
  2. Negotiated global congestion — PathFinder-style present and history costs for routability and channel pressure.
  3. Detailed A*/maze repair — rule-oracle costs, DRC markers, and PEX outliers to repair only implicated nets or clips.

Failure diagnosis classes

Every failure is classified — this is philis::router::RouteDiagnostic. Each class requires a different repair scope; an EOL violation near a via must not rip up a whole differential pair unless the local clip cannot be repaired while preserving pair symmetry.

  • no legal terminal access;
  • disconnected same-net component; different-net short;
  • DRC predicate violation;
  • color / cut-mask / stitch / via non-decomposability;
  • antenna or EM hard violation; IR-drop or current-density hard violation;
  • crosstalk/noise or coupling bound violation; PEX bound violation;
  • impossible analog constraint; PDK contradiction or missing rule data;
  • timeout without proof.

Each diagnosis also classifies scope: local repairable, global infeasibility, or unproven timeout. Repairable cases emit the smallest implicated net region and the exact failed predicate set; infeasible cases preserve the unsatisfied core / minimized conflict set rather than reporting "routing failed".

Rip-up scope minimization

Repair quality is governed by what gets torn up. Let V be the violation markers, imp(v) the resource edges implicated by marker v, owner(e) the net on edge e, and grp(n) the group-preserving closure of net n. The minimal rip-up scope is: 

seed(V)  = { owner(e) : e in imp(v), v in V }
scope(V) = closure over grp(.) of seed(V)

i.e. the smallest net set that (a) covers every implicated edge and (b) is closed under the group relation. Nets outside scope(V) are invariant across the repair step — the formal statement of "preserve unrelated clean geometry". Because scope(V) is a function only of committed state and the group relation, the selection is deterministic and replayable.

The group-preserving repair invariant

Joint structures (differential pairs, self-symmetric nets, common-centroid/interdigitated arrays, shield pairs) are protected by an invariant, not a soft penalty: 

INV_group: for every group g and every repair step,
  either all nets of g are simultaneously in scope(V) and rerouted under the
  group's joint objective, or none of g is rerouted.

The joint reroute preserves the group's geometric predicate (axis mirroring, equal per-layer length, equal via count, bounded skew/coupling asymmetry) as a hard local constraint solved by the exact engine. The certificate records, per group, the satisfied predicate and its residual deltas (max_diff_pair_skew_nm, max_length_match_delta_nm).

Convergence, termination, determinism

  • Monotone history cost. Each resource carries a present cost p(e) and a non-decreasing history cost h(e) ← h(e) + k·overflow(e), k > 0. A resource contested in the past stays expensive, asymmetrizing future tie-breaks and breaking the symmetric eviction cycle that causes oscillation.
  • Bounded budgets. RouteBudgets (max_iterations, max_repair_passes, max_runtime_ms) caps the loop, so termination is unconditional.
  • Best-verified retention. The loop keeps the lexicographically best verified state; on budget exhaustion it returns that state with unproven conditions explicitly marked — a timeout is a diagnosed outcome, never a silent bad route.
  • Determinism. Fixed net-family order, sorted/deduped rip-up scopes, segments/vias sorted by (net, layer, coords) before output, and fixed-order diagnostics. Any optional randomized net-order perturbation records its seed in the certificate, so even a randomized run is bit-reproducible.

Incremental DRC delta soundness

An incremental delta is sound only if it can never miss a violation a full check would catch. Every PDK predicate has a finite spatial influence radius r_max (max of its width, spacing, PRL, EOL, enclosure, density-window extents). When a commit changes geometry inside region Q, the delta re-evaluates all predicates over the dilation of Q by r_max, which provably contains every shape whose legality could have changed. Predicates with unbounded/context-global influence (large density windows, antenna accumulation along a full net) are flagged not delta-safe and re-run at tile/net scope. The certificate records which predicates were proven at clip vs. tile/net scope, so the soundness boundary is auditable.

Complexity: terminal access O(T·K) with O(K) local checks each; initial route O(N·|E_R|·log|E_R|); incremental verification scoped to the committed clip (O(m) DRC-delta for an m-edge commit plus near-constant union-find connectivity). The exact ILP/SMT engine is invoked only on small clips, so its cost is bounded by clip size, not by N.

9. The route certificate

The router returns geometry plus a certificate — the difference between "the router produced shapes" and "the router produced an auditable layout result". In Philis this is philis::router::RouteCertificate (see API Mapping). It contains:

  • route problem hash; PDK rule-oracle hash and signoff deck versions where available;
  • selected terminal access candidates and confidence levels;
  • route topology per net; generated shapes, patches, shields, vias, derived fill blockers;
  • connectivity proof or extracted graph;
  • DRC report (internal proof or external report path/hash);
  • LVS report and schematic mapping;
  • PEX canonical graph and reduced per-net parasitics;
  • IR drop, EM, antenna, crosstalk/noise evidence when applicable;
  • rule-coverage report in the canonical Coverage vocabulary;
  • analog constraint-satisfaction report; warnings and unsupported assumptions;
  • infeasible cores for failed nets.

The certificate distinguishes evidence classes. For each hard gate it carries one of three proof forms: an internal proof artifact, an external signoff report hash, or a solver counterexample record. A failing candidate stores the violating predicate IDs, the geometry/net identifiers, and the minimal reroute scope to reproduce the failure. A proven-infeasible problem preserves the unsatisfied core, so the result is not "the router failed" but "these predicates, shapes, and terminals are jointly inconsistent under this PDK, placement, and intent graph".
