Placement Algorithms & Foundations

This page derives, from first principles, the mathematical machinery the signoff-first formulation invokes. For each mechanism it states the math or the core idea, then maps it onto the realized Philis stage and the failure mode it addresses. The throughline is the lexicographic gate hierarchy: a mechanism either carves the feasible region (a hard or bounded gate) or searches inside it (a soft inner solver) — and nothing is permitted to do both.

Realized vs. target — read this first. Philis today ships a deterministic group packer plus an analytical centering/spacing pass; it is not yet a clause-learning SMT/CP-SAT search, an ePlace electrostatic optimizer, an SDP/optimal-transport matcher, a Benders/column-generation/ Lagrangian decomposer, or a thermal/LDE field oracle. Everything in the sections below labelled target is the contract the realized stage lowers into — the formal property a future back end must satisfy — not code that runs now. The honest stub status of every piece is tracked in crates/api/STUBS.md and on the API Mapping page. Where this page cites a realized identifier (philis::ACCEPTANCE_GATE_ORDER, philis::evaluate_gate_acceptance, philis::AcceptanceGate, philis::PlacementCertificate, philis::ConflictClass), it is verified against crates/api/src/core.rs. The exact/analytical function names (solve_discrete_assignments, refine_coordinates) and the module names (solve/exact, solve/analytical, solve/hybrid) are the paper's conceptual structure — they are not present in crates/api yet.

The inversion that organizes this page. Classical placement makes a stochastic or analytical optimizer the acceptance criterion and bolts on a late legality check. Philis makes the typed gates the acceptance criterion and demotes every optimizer — annealing, gradient descent, RL, diffusion — to a candidate generator. Learned and stochastic search proposes; the lexicographic gates dispose, and a rejected proposal returns a typed conflict core, never a silently worse score.

1. The hybrid solver, realized vs. target

The realized solver is two deterministic passes wrapped by a validating gate, not one global optimizer.

The exact stage — solve_discrete_assignments (solve/exact)

This stage fixes the discrete skeleton: it canonicalizes instance names, collects the symmetry / common-centroid / ordering companion groups, reorders centroid members into interdigitated slot order, and packs the groups left-to-right onto rows, returning an explored_nodes count. It is an exact-style packer — exact search is the conceptual frame — but as realized it is a deterministic greedy pass at O(n log n) with no proven discrete optimality. It addresses the failure mode where a wirelength gradient silently dissolves a matched group or picks an orientation the PDK forbids: here variant, orientation, row/region, symmetry axis, centroid pattern, and host binding are committed once, as a unit.

The analytical stage — refine_coordinates (solve/analytical)

A legality-preserving centering pass that distributes row slack while freezing every discrete choice. It is exactly the λ_A-only special case of the full differentiable objective of §4 — soft analog slack and centering, and nothing else — at O(iters·n). It addresses the failure mode where a discrete packer leaves devices jammed to one edge with avoidable asymmetric parasitics, without ever risking a legality-changing move.

The hybrid wrapper (solve/hybrid)

The wrapper validates that refinement changed neither cardinality nor any (instance, primitive_id, orientation) triple, then re-runs the local-DRC oracle before accepting — so the cheap analytical pass can never smuggle in an illegal or non-equivalent result. The realized solver path is recorded as PlacementCertificate::solver_path (e.g. "exact->analytical->legalize").

Determinism is a contract, not an accident. A seed in the input produces a seed / replay seed in the certificate (PlacementCertificate::seed), and two runs produce byte-identical output. This is guaranteed structurally: canonicalized instance names, BTreeMap/BTreeSet traversal order, evidence strings sorted into the certificate, and fixed tie-breaks at every branch. Reproducibility is what makes the self-adjusting re-evaluation of §13 sound and the conflict core auditable.

Target. The exact stage lowers into a clause-learning SMT / CP-SAT search whose explored_nodes becomes a real branch count and whose UNSAT core becomes the typed PlacementConflict set; the analytical stage lowers into the full electrostatic optimizer of §4. Both back ends are stubs today.

2. Quadratic assignment / facility location

Place units a onto slots under an assignment f; minimize interaction cost weighted by distance: 

min_f  Σ_{a,b} W[a,b] · D[f(a), f(b)]
       ≡  min  trace(W Xᵀ D X)     over permutation matrices X

This is the Quadratic Assignment Problem. It is NP-hard, admits no constant-factor approximation unless P = NP, and generalizes the TSP. The consequence is structural: Philis never runs exact assignment over a whole block. The realized block-level packer is the deterministic O(n log n) greedy pass of §1; exact search is reserved for the small, decomposed companion groups where the slot count is tiny. Well and region assignment is a separate QAP-like facility-location sub-problem, handled by the capacity-driven power diagram of §9 rather than by global enumeration.

3. Floorplan representations and the encoding-selection decision

The choice of floorplan encoding is itself a decision variable q_i ∈ {sequence-pair, B*-tree, O-tree, TCG, absolute integer grid}. The governing principle:

Pick the representation whose native invariant matches the sub-problem's dominant constraint, so the search space already excludes the infeasible region — rather than penalizing infeasibility after the fact.

Dominant constraintEncodingWhy it is native
Free-outline packing, few relations Sequence-pair A pair (Γ+, Γ-) of orderings; packing is a longest-path computation on the induced constraint graphs — every pair is a legal non-overlapping floorplan.
Incremental, non-slicing, area-driven B*-tree Contour/skyline packing in O(n); moves (rotate, swap, move) are local and cheap, ideal for an annealing inner loop.
Compact linear packing O-tree Smaller (2n + n⌈log n⌉)-bit state, O(n) packing — minimal encoding for tight linear arrangements.
Symmetry / common-centroid feasibility must be representation-native TCG Transitive-closure-graph edges make infeasible mirrorings unreachable — the symmetry invariant is encoded as graph structure, not a soft penalty.
Fixed-template lattice / FinFET row-fin-site / host-pin-anchored Absolute integer grid Lattice legality dominates free packing; symmetry becomes mirrored-coordinate equality x_a + x_a' = 2·x_axis; alignment is integer equality.
The realized engine uses the absolute-grid path. Placement runs on rows, a slot order, and interdigitated mirrored centroid slots (cf. philis::Strategy::CommonCentroid / Interdigitated in core.rs). The lattice is the row/fin/site grid the technology-compilation phase normalizes, so legality is a property of the coordinate type rather than a check run afterward.

4. Electrostatic analytical placement (the target smooth stage)

The target smooth stage — what refine_coordinates lowers into — replaces discrete packing with a differentiable objective.

  • Smooth wirelength. Replace the non-differentiable HPWL with log-sum-exp, (γ)·log(Σ exp(x_i/γ)), or a weighted-average approximation; γ controls the smoothing.
  • Density as electrostatic energy. Treat cell area as charge; density overflow becomes potential energy N = ½ Σ q_i ψ(x_i, y_i), with the potential ψ the solution of Poisson's equation −∇·(∇ψ) = ρ under Neumann boundary conditions, solved spectrally (FFT / cosine transform) in O(m log m). The gradient is the negative field −∇ψ.
  • Optimizer. Nesterov accelerated gradient with a Lipschitz-predicted steplength; the density weight λ_D is annealed so wirelength dominates early and legality (spreading) dominates late.

The full differentiable objective the analytical stage lowers into:

min  W_smooth
   + λ_D · density
   + λ_C · congestion
   + λ_P · parasitic_envelope
   + λ_A · analog_soft_slack
A smooth loss is never a substitute for a hard gate. The λ_A penalties apply only to bounded/soft constraints — symmetry-island proximity, regularity, current-flow compactness, common-centroid dispersion, coupling, template-boundary margin. Every hard PDK/LVS constraint is re-checked after rounding and legalization by the philis::AcceptanceGate::LocalDrc and DeviceEquivalence oracles. No finite λ may stand in for GateStatus::Pass.

5. Lexicographic and ε-constraint optimization

This is the mathematical justification for the gate hierarchy itself.

  • Lexicographic optimization for the hard gates G0–G4: solve level k, assert its zero-violation / ε-optimum as a hard constraint, then continue to level k+1. This is exactly philis::ACCEPTANCE_GATE_ORDER evaluated under philis::evaluate_gate_acceptance — a level can never be traded against a lower one.
  • ε-constraint (Mavrotas augmented) for the bounded G5 budgets: hold f_j ≤ ε_j for each PEX / EM / noise / LDE / thermal envelope while optimizing the remainder.
  • Weighted scalarization confined to the soft R6 tail — the only place weights are permitted (parasitics, area, HPWL, density, DFM, runtime).

No finite weight can guarantee a hard property when it conflicts with wirelength. A nonzero hard violation is a different feasibility class, not a worse score — which is precisely what the HardVector lexicographic relation in core.rs encodes for the routing sibling, and what the gate stack encodes for placement.

6. Spatial indexing

The geometric back ends behind the delta-record affected_objects set and the local-DRC spacing test.

  • Corner-stitching (Ousterhout): represent empty space as explicit tiles alongside solid ones; edits and neighbor queries are near-constant-time, and incremental DRC walks the tile structure Magic-style. Used for the edit-heavy regions a legalize/repair loop churns.
  • R-trees: minimum bounding rectangles with O(log n) window queries and STR bulk-load. Used for the query-heavy static snapshots — the read-mostly geometry the access and routability oracles probe.

Together they back the change-scoped re-evaluation of §13: corner-stitching localizes the edit, the R-tree answers the spacing/window query against the frozen snapshot.

7. OR decomposition

When a block is too large for monolithic exact search, decompose it. Each method also yields the certificate artifact Philis needs.

MethodDecompositionCertificate artifact
Logic-based Benders A master over the discrete decisions; a coordinate subproblem checks feasibility. An infeasibility cut becomes a typed philis::PlacementConflict / infeasible core.
Column generation / Dantzig-Wolfe Centroid and folding patterns are columns; a pricing subproblem generates promising ones. The active pattern set with reduced-cost evidence.
Lagrangian relaxation Dualize the linking non-overlap / capacity constraints into per-group subproblems. A lower bound, hence a certified optimality gap for the R6 soft tail.

8. SDP and optimal transport

Two relaxations of the unit-to-slot matching, both confined to soft / bounded matching quality — never a hard gate.

  • SDP relaxation of the QAP. Lift X to Y = vec(X)·vec(X)ᵀ ⪰ 0 with doubly-stochastic row/column sums; the relaxation is often tight, and a tight one rounds to a near-optimal permutation.
  • Optimal transport / Sinkhorn dispersion. Treat slot assignment as a transport plan; entropic (Sinkhorn) regularization yields a differentiable doubly-stochastic plan that anneals to a permutation — a smooth λ_A dispersion penalty for common-centroid spreading.

9. Power diagrams + Minkowski sums

The exact-geometry foundations of region assignment and the spacing predicate.

  • Power diagram (weighted Voronoi): cell(s_i) = { p : |p − s_i|² − ω_i ≤ |p − s_j|² − ω_j ∀ j }. By Aurenhammer's theorem the weights ω_i drive the cell areas to prescribed values, which is exactly what a capacity-constrained well / region assignment needs: tune weights until each region's area matches its device load.
  • Minkowski sum. Dilating a shape by a spacing ball, A ⊕ B_δ, turns a spacing query into a point-in-polygon containment test. This is the exact-geometry core of the local-DRC spacing predicate behind philis::AcceptanceGate::LocalDrc and of guard-ring / high-voltage keepout checks.

10. Robust / chance-constrained PVT-and-mismatch budgeting

A bounded G5 budget that holds across process, voltage, temperature, and random mismatch — not just at the nominal corner. 

Robust:            max_{u ∈ U}  f_j(x, u)  ≤  ε_j
Chance:            Pr[ f_j(x, ξ) ≤ ε_j ]  ≥  1 − α
Gaussian SOC form: μ_j(x) + Φ⁻¹(1−α) · σ_j(x)  ≤  ε_j

The chance constraint, under a Gaussian model, becomes a second-order-cone constraint on the mean and standard deviation of the budgeted quantity. Pelgrom's law, σ ∝ 1/√(W·L), ties device area and folding directly to mismatch robustness — which elevates mismatch from a geometric proxy to a budgeted G5 gate rather than a soft afterthought.

11. Compact thermal RC

A lumped thermal network: heat capacitance C, conductance G, power injection P. 

Transient:   C · (dT/dt) + G · T = P
Steady:      G · T = P      ⇒      T = G⁻¹ P
Coupling:    G off-diagonal  1/R_ij  with  R_ij = length / (k · A_contact)

The off-diagonal conductances are set by floorplan adjacency — so the placement is the thermal model. Move two power devices apart and you have changed G.

This feeds a bounded thermal-gradient constraint at G5 and a soft peak-temperature term in R6, and is mandatory for CFET vertical assignment, where stacked tiers share a thermal path. The oracle is a stub today (Coverage::Missing).

12. Layout-dependent-effect physics

Device parameters shift with the surrounding layout. Two dominant effects, both posynomial / geometric-program compatible:

  • Well-proximity effect (WPE). ΔV_th = KVTH0WE · (SCA + WEB·SCB + WEC·SCC), where the SC* are monotone-decaying well-edge-distance integrals. Matched pairs therefore need equal well-edge distances.
  • STI / LOD stress. Mobility/threshold shift decaying in OD-edge distance, with opposite sign for PMOS vs. NMOS.

These enter as a hard equality for matched groups — realized today only as a T0 dummy-ring / equal-edge-context proxy — and as a bounded ΔV_th / Δμ budget at G5 once the LDE oracle lands.

TierFidelityCoverage class
T0Geometric proxy (dummy ring, equal edge context)Missing

Placement (and the companion thermal model of §11) runs at T0 today: a geometric proxy that produces a degraded_confidence certificate, never a signoff claim.

13. Self-adjusting computation

A dynamic dependence graph with change-propagation backs the delta-record-keyed, group-scoped re-evaluation — and guarantees the reused result is bit-identical to a from-scratch run (which the determinism contract of §1 makes possible). The invalidation scope is two-tiered:

ChangeInvalidates
variant · orientation · region · row · host-binding · access · route-reservation only the affected local records (group-scoped)
PDK coverage · host template · extraction model · primitive generator the whole certificate

The first tier is what makes the conflict-directed repair loop cheap; the second is why a PDK or oracle change cannot be patched locally — it moves the feasible region itself.

14. The search-heuristic lineage, framed honestly

The classical placement literature is a lineage of candidate generators. Philis treats every one of them as an inner solver under the hard gates — never as the acceptance criterion.

HeuristicMechanismRole in Philis
Simulated annealing (TimberWolf) Metropolis acceptance exp(−ΔE/T), cooling α ≈ 0.95. Proposes moves on a floorplan encoding (§3).
Parallel tempering Replica exchange across temperatures; seeded for reproducibility. Deterministic when seeded — fits the §1 contract.
RL floorplanners Relational-GNN encoder + RL agent with a routing-aware reward. Generates discrete skeletons; reward is advisory, not acceptance.
Generative / diffusion (LayoutDM) Learned generative layout distribution. Samples candidates; every sample is gated.

The key inversion. Any proposal that violates a hard gate is rejected with a typed conflict core (philis::PlacementConflict via philis::ConflictClass::gate), not merely scored lower. Learned and stochastic search proposes; the typed gates dispose. This is the same discipline that lets the realized deterministic packer stand in for a future SMT search without changing the acceptance relation — the optimizer can be swapped freely because it was never load-bearing for soundness.
