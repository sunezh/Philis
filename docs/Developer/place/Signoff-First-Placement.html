The Signoff-First Placement Problem

This page is the formal specification the Philis placer is built against. It is the implementable form of papers/placement/spout-placement-problem-setup.md — "A Signoff-First, PDK-Aware Problem Formulation and Certificate Contract for Analog Placement" — with every symbol tied to a Philis type where one exists (see API Mapping & Stubs). Placement is the upstream sibling of the router: the two share one canonical signoff vocabulary, and the placer's RouterHandoffWitness is exactly the readiness evidence the router consumes.

What is ideal and what is real. This page describes the ideal formulation — the contract the placement engine must satisfy. The realized Philis engine is a stub: the contract types (in crates/api/src/core.rs) are real and unit-tested, but the gate evaluator that proves their contents is not wired — philis::run_placement emits philis::PlacementCertificate::stub(), every gate Degraded. Throughout, philis::… identifiers name things that exist now; everything else is labelled target / conceptual. The precise stub ledger is crates/api/STUBS.md.

1. Problem statement

Given a schematic netlist, a design hierarchy, a PDK bundle, a primitive/generator library, a host template or fixed-GDS shell, any fixed geometry, and explicit-plus-inferred design intent, produce placed device geometry together with a machine-checkable certificate such that:

  1. every primitive is generated from a PDK-supported, LVS-equivalent device;
  2. every transform, orientation, row/fin-site, well, implant, guard, tap, dummy, abutment, and keepout is PDK-legal;
  3. there is no placement-level DRC violation;
  4. every terminal has a legal, typed access map and a routable access pattern, or the problem is reported infeasible;
  5. every fixed host-interface object (padframe, tile pins, rails, hard-macro pins, seal rings) is treated as an immutable boundary;
  6. all required analog intent is satisfied or diagnosed;
  7. there is enough routability and parasitic margin for a router to reach DRC=0 / LVS=true;
  8. an infeasible case returns an unsatisfied-core diagnosis, not a guessed placement.

The certificate is the placement's companion proof: a result is auditable rather than anecdotal precisely because every claim above is backed by an evidence-carrying oracle, and a failure preserves its conflict core rather than reporting a bare "placement failed".

2. The input tuple

I = (T, S, H, G, M, C, O, B)
  • T — the compiled technology model.
  • S = (D, N, ports) — the schematic graph of devices D, nets N, and terminals.
  • H — the design hierarchy graph (subcircuits, repeated blocks, reuse).
  • G — the primitive source catalog: PCells / parameterized generators, templates, imported cells, black boxes, and fixed geometry.
  • M — the host layout contract.
  • C — explicit plus inferred constraints, lowered into the IntentGraph.
  • O — obstacles / keepouts / wells / guards / pads / seal-rings / reserved routes.
  • B — the budget vector: runtime, memory, area, parasitic bounds, EM/noise margins, allowed degraded behavior, and external signoff hooks.

3. The compiled technology model

The PDK compiler is the critical boundary: it turns process-specific data into stable, typed oracles. The target CompiledPlacementTechnology is the ten-tuple 

T = (U, L, R, P, A, X, K, D, Q)
  • U — units, manufacturing grid, placement lattice, row sites, fin pitch, legal rotations + reflections, color masks.
  • L — layer roles: active, poly, local interconnect, metals, wells, implants, markers, vias, RDL, pad, inductor / resistor / capacitor, keepout.
  • R — placement-relevant rule predicates: spacing, enclosure, overlap, min-area, notch, well/tap distance, latch-up, HV isolation, density, coloring, row/fin, antenna preconditions, region restrictions.
  • P — the primitive catalog: legal variants, generated geometry, terminal maps, parameter-equivalence proofs, local-DRC evidence.
  • A — the abutment / sharing algebra: diffusion / dummy / guard sharing, well merging, tap reuse, via-in-pin, same-template copy.
  • X — the extraction model: device equivalence plus early parasitic / LDE prediction.
  • K — the routability model: pin-access candidates, track/via resources, channel capacity, preferred directions, blockage effects.
  • D — the DFM / fill / CMP / litho model.
  • Q — the rule/deck coverage inventory, keyed by at least (rule_id, device_or_layer_scope, corner, mode, deck_id, host_template_id).
Realized. The conceptual CompiledPlacementTechnology is the target; today the realized engine is a stub. Its readiness rollup, however, is a real type: philis::PdkState (FullSignoff | AbstractComplete | SparseResearch | ContradictoryOrMissing), classified conservatively from the per-predicate coverage buckets and the structural sanity of layers/tracks/vias. A stub PDK is SparseResearch.

4. The host layout contract

The target host contract is

M = (frame, outline, fixed_pins, fixed_nets, rails, padframe,
     seal_ring, wrappers, obstructions, reserved_layers, export_rules)
  • fixed_pins are immutable — never moved to suit wirelength.
  • rails carry continuity rules across the block.
  • export_rules cover LEF / GDS / DEF naming and shuttle restrictions.

A host template or fixed-GDS shell is a set of boundary conditions, not suggestions. Realized today: outline, fixed pins, and obstacles (rails / padframe / seal-ring / export handled in simplified form). The fixed host-interface objects respected by a run are surfaced as philis::RouterHandoffWitness::host_pin_count, and a conflict that would require altering one is classed philis::ConflictClass::HostInterface (blamed against the LocalDrc gate — see philis::ConflictClass::gate).

5. The IntentGraph

The constraints layer's symmetry, ordering, alignment, and common-centroid projections are lowered into a deterministic IntentGraph. The full target intent vocabulary includes symmetry, ordering, alignment, common-centroid, proximity, interdigitation, ratio-matching, same-template, current-flow, parallel-current-path, system-signal-flow, differential pairs, sensitive nets, shields, power / substrate domains, guard-rings, taps, dummies, isolation, HV domains, RF classes, thermal groups, host-IO binding, route reservations, and hierarchy. Each edge carries an obligation class. A CommonCentroidGroup (target) is a tuple of unit-device assignments, allowed patterns, a dummy policy, and parasitic-match budgets.

Realized. The compiled Constraint taxonomy (philis::Constraint) is lowered onto obligation classes by philis::Constraint::intent_class. Engine- unsupported variants map to IntentClass::Unsupported and surface as philis::BuildWarning::UnsupportedConstraint — never silently dropped. Widening the realized intent vocabulary (current-flow, system-signal-flow, thermal groups, full centroid groups) is target work tracked on the overview.

6. Obligation & coverage vocabulary

ObligationClass

The canonical ObligationClass, owned by the constraints layer, has seven members:

ClassMeaning
HardA violation is unacceptable — a gate failure.
JointMembers move together (both sides of a symmetry pair); one side is never moved alone.
BoundedAdmissible only within an explicit numerical tolerance.
SoftOptimized only after every hard gate passes.
UnsupportedRefused or reported degraded before solving.
ExternalOnlyAn evidence location: blocks a signoff claim until an external deck supplies the evidence.
ManualReviewAn evidence location: blocks a signoff claim until a human note supplies the evidence.

The realized Philis enum is the four-member philis::IntentClass { Hard, Bounded, Soft, Unsupported } (with tag() and is_gate() — only Hard is a gate), mapped from the philis::Constraint taxonomy by philis::Constraint::intent_class. Closing the gap to the canonical contract means adding Joint, ExternalOnly, and ManualReview.

Coverage

philis::Coverage is realized with all nine canonical members, shared verbatim with routing: 

Coded | Partial | Approximate | ExternalOnly | ManualReview |
RecommendedOnly | Unsupported | Missing | Contradictory

A rule reported with internal evidence but no required deck reads as signoff-ready, not signoff-quality. Contradictory triggers an early inconsistency core. The per-predicate buckets roll up into philis::PdkState { FullSignoff, AbstractComplete, SparseResearch, ContradictoryOrMissing }, and the per-class counts live in philis::RuleCoverageReport (whose count(Coverage) and as_map() project the legacy bucket names onto the canonical enum). The realized Coverage enum is wider than the realized IntentClass — coverage is the fully-built half of the vocabulary.

8. The hard feasibility constraint set

Hard feasibility is the conjunction

F = F_pdk ∧ F_device ∧ F_template ∧ F_place ∧ F_intent ∧ F_access ∧ F_signoff

Each conjunct is a typed oracle that reports facts-with-evidence, not policy: it answers "does this predicate hold, and what is the proof?" rather than "is this a good placement?". The placer queries them during candidate generation and repair, never as a late afterthought.

OracleRealized scopeGap
local-DRC (F_place) Partial — overlap, grid, outline, host-obstacle predicates enclosure / well / implant / color rule families
device-equivalence (F_device) Partial — class / model / terminal-order / bulk / W-L / multiplicity / folding imported cells need trusted terminal + extraction maps
terminal-access (F_access) Partial — the access set must be non-empty full via-stack / obstruction families
routability (part of F_access) Partial — channel reservations + capacity witnesses congestion coupling

The target terminal-access oracle certifies, for each terminal t, a non-empty access set: 

Access(t) = { (point, layer, direction, via_stack,
              enclosure_context, obstruction_hash, paired_group_id) }   ≠ ∅

F_pdk (the PDK is covered for the required classes) and F_template (the host contract is respected) and F_intent (hard analog intent holds) complete the set. F_signoff — the electrical-margin conjunct — is the one not yet served by any realized oracle.

Missing oracles. The PEX / EM / noise / LDE / thermal oracles are Missing today. They are what F_signoff would feed; until they exist (or are declared ExternalOnly), any result touching an electrical budget is degraded_confidence and a philis::ConflictClass::ParasiticBudget conflict can only be raised on external evidence.

9. The lexicographic acceptance hierarchy

Hard feasibility is never traded for lower parasitics. Acceptance is a stack of gates; the soft objective is compared only once every gate holds. There are two orderings, and the distinction matters. 

Design-rationale order  (how a designer reasons, most fundamental first)
  G0  TechnologyCoverage   required PDK / host / rule coverage exists
  G1  DeviceEquivalence    every device & imported cell is LVS-equivalent
  G2  LocalDrc             placement-owned local DRC, non-overlap, host legality
  G3  IntentSatisfaction   all hard analog intent (symmetry, order, centroid…)
  G4  TerminalAccess +     every terminal has access; channels have capacity
      Routability
  G5  (bounded)            PEX / EM / noise / LDE / thermal envelopes  — ε-bound
  R6  (soft)               parasitics, area, HPWL, density, DFM, runtime — weights

Realized acceptance order  (philis::ACCEPTANCE_GATE_ORDER, enforced in code)
  TechnologyCoverage → LocalDrc → DeviceEquivalence →
  TerminalAccess → Routability → IntentSatisfaction

G0–G4 are hard gates; G5 is a bounded ε-constraint; R6 is the soft tail — the only place weights are permitted. The realized order (philis::ACCEPTANCE_GATE_ORDER, six philis::AcceptanceGate variants, each with name() and is_repairable()) reshuffles two gates on purpose:

  • LocalDrc precedes DeviceEquivalence because by this point the geometry already exists, local DRC is the cheapest high-yield rejector, and equivalence is invariant under legalization — deferring it one slot costs no soundness.
  • IntentSatisfaction runs last because it is the gate that is repairable before legalization: a symmetry/centroid group can be re-mirrored, so it is the natural last thing to settle.

Only LocalDrc and IntentSatisfaction are repairable (philis::AcceptanceGate::is_repairable); the other four are terminal — a missing deck, generator, access set, or channel capacity cannot be conjured by moving geometry. The policy is philis::evaluate_gate_acceptance(gates, allow_repairable_failures), called twice: 

pre-legalization   evaluate_gate_acceptance(gates, true)
                   // a Fail on a repairable gate is "repair-pending", not a reject
post-legalization  evaluate_gate_acceptance(gates, false)
                   // any Fail rejects; Degraded never rejects

The order governs which violation is blamed first, never whether an accepted result is sound — acceptance requires every gate. The target formulation names three incremental-lexicographic mechanisms — (a) assume-optimum-then- next-gate, (b) assumption literals lowered to an unsat core, and (c) warm starts with group-scoped re-evaluation — of which only the warm starts and group re-evaluation are realized today.

10. Legalize-and-repair loop

Group-preserving legalization snaps geometry to the lattice, removes overlaps, repairs spacing, and re-mirrors symmetry and common-centroid groups jointly — it never moves one side of a matched pair alone. The target formulation emits LegalizationAction records (conceptual) so every snap and re-mirror is auditable.

When legalization cannot satisfy a gate, conflict-core extraction emits typed conflicts. The realized type is 

philis::PlacementConflict {
    class: ConflictClass,
    scope: DiagnosticScope,
    message: String,
    subjects: Vec<String>,    // the minimal repair seed (implicated instances/groups)
    predicates: Vec<String>,  // the violated rule / intent IDs
}

with philis::ConflictClass mapping each conflict to a blamed gate:

ConflictClassBlamed gate (ConflictClass::gate)
CoverageGapTechnologyCoverage
PdkRuleLocalDrc
HostInterfaceLocalDrc
DeviceEquivalenceDeviceEquivalence
TerminalAccessTerminalAccess
CapacityRoutability
ParasiticBudgetRoutability
IntentViolationIntentSatisfaction

A repairable conflict carries the smallest implicated group as a repair seed; an infeasible one is preserved in the certificate's infeasible_core. The scope reuses routing's philis::DiagnosticScope (LocalRepairable | GlobalInfeasible | UnprovenTimeout). Proven minimality of the core is a target — today the core is emitted not_minimized.

11. The ownership matrix

Placement owns a specific slice of the signoff problem; it shares some and disowns the rest. Confusing the rows is how an analog flow ends up claiming a signoff it cannot back.

12. The placement certificate

The placer returns geometry plus the realized philis::PlacementCertificate, never geometry alone: 

philis::PlacementCertificate {
    problem_hash: u64,
    pdk_oracle_hash: u64,
    pdk_state: PdkState,
    gates: Vec<GateEvaluation>,            // in ACCEPTANCE_GATE_ORDER
    coverage: RuleCoverageReport,
    degraded_confidence: bool,
    degraded_causes: Vec<DegradedConfidenceCause>,
    handoff: RouterHandoffWitness,         // placement → router readiness evidence
    infeasible_core: Vec<PlacementConflict>,
    solver_path: String,                   // e.g. "exact->analytical->legalize"
    seed: Option<u64>,
}
  • philis::GateEvaluation { gate, status, evidence } with philis::GateStatus { Pass, Degraded, Fail } — one verdict per gate, with an evidence string sorted in for determinism.
  • philis::DegradedConfidenceCause { gate, reason, coverage } — why a result is signoff-ready shaped rather than signoff-quality, carrying the Coverage class of the missing evidence.
  • philis::RouterHandoffWitness { has_access_map, reserved_channel_count, terminal_count, host_pin_count, obstruction_count, note } — the placement→router readiness evidence, the input the router's access and capacity oracles consume.

PlacementCertificate::is_signoff_quality() is true only when every gate Passed on coded evidence and the result is not degraded; is_accepted() is true when no gate hard-failed (it may still be degraded).

The stub is honest. philis::run_placement emits PlacementCertificate::stub(): every gate Degraded, pdk_state = SparseResearch, degraded_confidence = true, and a handoff witness noting "engine stub — no access map". It is feasible-shaped (nothing is proven wrong, so is_accepted() holds) but never signoff-quality (is_signoff_quality() is false) — a stub result can never be mistaken for a proven placement.

13. The case taxonomy

A signoff-first placer must behave correctly — and report honestly — across five orthogonal axes. The contract is not "always produce a placement"; it is "produce a placement, or a proof, with confidence labelled by where on these axes the input falls".

AxisRange (easiest → hardest / most predictive)
Process node mature planar CMOS · mixed-signal / RF / HV / BCD · scaled planar · FinFET (colored, unidirectional) · GAA / CFET / backside-power / monolithic-3D (predictive)
PDK completeness full signoff decks · abstract-but-complete · sparse academic · contradictory / missing
Circuit intent ordinary · differential / symmetric · matched arrays / interdigitation / common-centroid · power / guard / substrate / HV / ESD · RF / passives · current-flow / system-signal-flow
Geometry source generated primitives with exact pins · imported cells / black boxes · fixed macros / blockages · host templates / padframes · no legal primitive / no route channel
Verification state clean / signoff-ready · repairable local violation · degraded coverage · proven infeasible
Advanced nodes are predictive. For GAA / CFET / backside-power / monolithic-3D, the technology coverage is Approximate or Missing unless the PDK supplies vertical-stack, backside-rail, thermal, and extraction rules — so a result there is degraded_confidence by default. CFET in particular makes thermal a first-class placement constraint, not a downstream check: device stacking couples heat paths that placement, not routing, commits.

The most honest behaviors at the hard end of each axis are exactly the ones the certificate is built to express: a contradictory / missing PDK promotes pdk_state to ContradictoryOrMissing and yields an early inconsistency core; a no legal primitive / no route channel input yields a DeviceEquivalence or TerminalAccess conflict; and a proven infeasible problem returns its preserved infeasible_core rather than a guessed placement.

The algorithms page derives the machinery the back ends behind these oracles will use; the API Mapping & Stubs page pins every symbol above to its exact crates/api type and stub status.
