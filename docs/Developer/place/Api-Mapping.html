Placement API Mapping & Stubs

This page ties the signoff-first formulation to the concrete Philis surface — the philis crate (crates/api) — and states precisely, identifier by identifier, what is real today versus a documented stub. It is the placement counterpart of the router's API Mapping page, and it is the most exacting of the four placement pages: every type and method named below was read out of the source, not paraphrased from the paper. The honesty rule from the API design rules applies verbatim — the one defect the design forbids is an API that accepts input it silently discards.

Where the placement contract lives. The signoff-first placement vocabulary lives in crates/api/src/core.rs, in the Signoff-first placement contract section that sits alongside the stage oracles and the routing contract in the same module. It is re-exported flat at the crate root as philis::* and, mirroring the eventual split into separate engine crates, under the philis::placer and philis::next::placer namespaces. The stage oracle is core::run_placement. Crucially, the placement contract shares routing's canonical signoff vocabulary — Coverage, PdkState, RuleCoverageReport, and DiagnosticScope are all defined once (in the routing-contract part of core.rs) and reused by placement.
The gate evaluator is a stub; results are degraded-confidence. The contract types are real and unit-tested, but the gate evaluator, the typed oracles (drc / equivalence / access / routability), the hybrid solver, and group-preserving legalization are all stubs. run_placement emits PlacementCertificate::stub(): every acceptance gate is GateStatus::Degraded, pdk_state is the conservative PdkState::SparseResearch, and degraded_confidence = true. A stub result is therefore signoff-ready shaped but can never be mistaken for signoff-quality. The full ledger is crates/api/STUBS.md.

1. Overview

A signoff-first placer returns geometry plus a machine-checkable certificate, never geometry alone, and acceptance is a lexicographic hierarchy of hard gates — technology coverage → local DRC → device equivalence → terminal access → routability → intent satisfaction — gated before any soft objective (area, HPWL, parasitics). In Philis this contract is a sibling of the routing contract in the same core.rs module, and it deliberately reuses routing's canonical Coverage / PdkState / RuleCoverageReport / DiagnosticScope vocabulary so that the constraints layer owns one signoff lexicon and placement and routing share it. The current state is shape-real, behavior-stub: the typed surface is complete and exercised by tests (placement_tests in core.rs), while the engine that would prove the certificate's contents is the stub run_placement.

2. The paper's conceptual types → the realized Philis surface

The research formulation is written against a sibling workspace's crate (crates/placer2). The table maps its load-bearing shapes onto the Philis types that exist in core.rs today. Field lists are reproduced exactly from the source.

The four Missing / target shapes in the last row are the aspirational engine types. They are named in the pipeline overview but have no Rust representation in crates/api today; do not reach for them in code.

3. The acceptance gates in code

philis::AcceptanceGate is a six-variant #[non_exhaustive] enum, and philis::ACCEPTANCE_GATE_ORDER is the [AcceptanceGate; 6] array giving the realized evaluation order (which differs from the design-rationale order — see the overview): 

pub const ACCEPTANCE_GATE_ORDER: [AcceptanceGate; 6] = [
    AcceptanceGate::TechnologyCoverage,
    AcceptanceGate::LocalDrc,
    AcceptanceGate::DeviceEquivalence,
    AcceptanceGate::TerminalAccess,
    AcceptanceGate::Routability,
    AcceptanceGate::IntentSatisfaction,
];

Each gate carries AcceptanceGate::name() -> &'static str (the exact string used in the certificate) and AcceptanceGate::is_repairable() -> bool, which is true for only LocalDrc and IntentSatisfaction — group-preserving legalization can re-snap geometry and re-mirror a symmetry pair, but it cannot conjure a missing rule deck, device generator, terminal-access set, or channel capacity, so the other four gates fail terminally. A gate's verdict is a GateStatus { Pass, Degraded, Fail } (default Degraded — a gate with no evidence is degraded, not passing), and one gate's evaluation is a GateEvaluation { gate, status, evidence } where evidence is a String.

The acceptance policy is the free function evaluate_gate_acceptance(gates: &[GateEvaluation], allow_repairable_failures: bool) -> bool. It is called twice by the pipeline: pre-legalization with true (a Fail on a repairable gate is recorded as repair-pending, not a reject) and post-legalization with false (any Fail is a hard reject). Degraded never rejects. 

use philis::{
    AcceptanceGate, GateEvaluation, GateStatus,
    ACCEPTANCE_GATE_ORDER, evaluate_gate_acceptance,
    run_placement, PlacementRunInput,
};

// Build a gate vector (here: every gate passes on coded evidence).
let gates: Vec<GateEvaluation> = ACCEPTANCE_GATE_ORDER
    .iter()
    .map(|&gate| GateEvaluation {
        gate,
        status: GateStatus::Pass,
        evidence: format!("{}: ok", gate.name()),
    })
    .collect();

// Pre- and post-legalization acceptance under the repairable-failure policy.
let accepted_pre = evaluate_gate_acceptance(&gates, true);
let accepted_post = evaluate_gate_acceptance(&gates, false);
assert!(accepted_pre && accepted_post);

// Only LocalDrc and IntentSatisfaction may be repaired before legalization.
assert!(AcceptanceGate::LocalDrc.is_repairable());
assert!(!AcceptanceGate::Routability.is_repairable());

// The stub oracle: feasible-shaped but never signoff-quality.
let result = run_placement(&PlacementRunInput { device_count: 3 });
let cert = &result.certificate;
assert!(cert.is_accepted());          // no hard fail
assert!(!cert.is_signoff_quality());  // but degraded-confidence

4. The certificate & router handoff in code

philis::PlacementCertificate is geometry's companion proof. Its fields, exactly as declared: 

pub struct PlacementCertificate {
    pub problem_hash: u64,                          // hash of (T, S, H, M, C, O, B)
    pub pdk_oracle_hash: u64,                        // hash of the compiled PDK oracle
    pub pdk_state: PdkState,                          // shared with routing
    pub gates: Vec<GateEvaluation>,                   // per-gate verdicts, in ACCEPTANCE_GATE_ORDER
    pub coverage: RuleCoverageReport,                // per-class rule coverage
    pub degraded_confidence: bool,                   // signoff-ready *shaped*, not quality
    pub degraded_causes: Vec<DegradedConfidenceCause>,
    pub handoff: RouterHandoffWitness,               // placement → routing contract
    pub infeasible_core: Vec<PlacementConflict>,     // preserved unsat core on failure
    pub solver_path: String,                         // e.g. "exact->analytical->legalize"
    pub seed: Option<u64>,                            // placement is deterministic in its seed
}

Two predicates read the certificate. is_signoff_quality() is true iff the result is not degraded and the gate vector is non-empty and every gate is GateStatus::Pass — a genuine readiness claim. is_accepted() is true iff no gate hard-failed (it may still be degraded-confidence); it is exactly a post-legalization evaluate_gate_acceptance(&self.gates, false). The constructor PlacementCertificate::stub() is the honest placeholder: it fills gates with every gate Degraded, sets pdk_state = PdkState::SparseResearch, degraded_confidence = true, one DegradedConfidenceCause per gate (each with Coverage::Missing), a RouterHandoffWitness with the note "engine stub — no access map", and solver_path = "baseline (stub)". So a stub certificate is is_accepted() but not is_signoff_quality().

The router handoff is philis::RouterHandoffWitness — the placement readiness witness the router consumes, evidence that a route toward DRC=0 / LVS=true is reachable, not the routed result: 

pub struct RouterHandoffWitness {
    pub has_access_map: bool,            // every terminal has >= 1 access candidate
    pub reserved_channel_count: usize,   // channels reserved for matched/shielded/critical nets
    pub terminal_count: usize,           // schematic terminals with a typed access set
    pub host_pin_count: usize,           // fixed host-interface pins as boundary conditions
    pub obstruction_count: usize,        // obstruction snapshots (hash count for stability)
    pub note: String,                    // human-readable note (degraded reason on a stub)
}

A degraded cause is philis::DegradedConfidenceCause { gate: AcceptanceGate, reason: String, coverage: Coverage } — the gate that degraded, why, and the coverage class of the evidence that was unavailable.

A finished Layout surfaces all of this without a .gds dump. Layout::certificate() -> &PlacementCertificate returns the placement certificate, Layout::router_handoff() -> &RouterHandoffWitness returns its handoff field, and Layout::is_signoff_quality() -> bool forwards to the certificate's predicate — so under the stub engine it is honestly false. 

let cert = layout.certificate();          // &PlacementCertificate
let handoff = layout.router_handoff();    // &RouterHandoffWitness
let ready = layout.is_signoff_quality();  // false under the stub engine

5. Intent classes & the Constraint taxonomy

philis::IntentClass is how strongly the engine must honor an analog-intent obligation. The canonical ObligationClass owned by the constraints layer has seven members (Hard | Joint | Bounded | Soft | Unsupported | ExternalOnly | ManualReview); the realized engine encodes four: 

pub enum IntentClass { Hard, Bounded, Soft, Unsupported }

impl IntentClass {
    pub const fn tag(self) -> &'static str { /* "hard" | "bounded" | "soft" | "unsupported" */ }
    pub const fn is_gate(self) -> bool { matches!(self, IntentClass::Hard) }  // only Hard is a gate
}

Constraint::intent_class() lowers the constraint taxonomy onto these classes:

Constraint variantsIntentClass
Symmetric, SelfSymmetric, SymmetricGroup, Order, Align, GuardRingHard (a gate — a violation is electrically wrong)
Matching, DistanceConstraintBounded (admissible only inside a numerical tolerance)
NetShield, SetNetClassSoft (optimized only after every hard gate passes)
the 12 engine-unsupported variants (SignalFlow, AspectRatio, CellBoundary, FixPosition, PlaceOnGrid, PlaceOnBoundary, Group, PortLocation, NetMatch, MultiWire, DoNotRoute, ChargeFlow)Unsupported

The Unsupported set is exactly the complement of Constraint::is_engine_supported(), and it is precisely the set that the builder surfaces as BuildWarning::UnsupportedConstraint(kind) at build time. That is the honesty property: an engine-unsupported constraint lowers to IntentClass::Unsupported and is reported, never silently dropped.

6. The conflict core in code

A typed conflict is philis::PlacementConflict { class, scope, message, subjects, predicates } — the placement analog of routing's RouteDiagnostic. It carries the implicated instances/groups (subjects: Vec<String>, the minimal repair seed) and the violated rule / intent IDs (predicates: Vec<String>). Its scope reuses routing's DiagnosticScope { LocalRepairable, GlobalInfeasible, UnprovenTimeout }. Its class is the eight-variant ConflictClass, and ConflictClass::gate() names the gate each is blamed against:

ConflictClassConflictClass::gate()
CoverageGapAcceptanceGate::TechnologyCoverage
PdkRule, HostInterfaceAcceptanceGate::LocalDrc
DeviceEquivalenceAcceptanceGate::DeviceEquivalence
TerminalAccessAcceptanceGate::TerminalAccess
Capacity, ParasiticBudgetAcceptanceGate::Routability
IntentViolationAcceptanceGate::IntentSatisfaction

On an infeasible problem the conflict set is preserved as the certificate's infeasible_core: Vec<PlacementConflict> rather than reported as a bare "placement failed". Minimality of that core is not yet proved (see the roadmap).

7. The shared signoff vocabulary

The placement contract does not own a parallel coverage lexicon. Coverage (nine variants: Coded, Partial, Approximate, ExternalOnly, ManualReview, RecommendedOnly, Unsupported, Missing, Contradictory), PdkState (four: FullSignoff, AbstractComplete, SparseResearch, ContradictoryOrMissing), and RuleCoverageReport are all defined in the routing-contract part of core.rs and reused by placement (DegradedConfidenceCause::coverage and PlacementCertificate::{pdk_state, coverage} are these very types). One canonical source — matching the paper's "constraints layer owns the vocabulary, placement and routing share it." All of these names are re-exported flat at the crate root as philis::Coverage, philis::PdkState, etc.

8. The verify seam

philis::verify::{drc, lvs, pex, erc} and the matching Layout::{drc, lvs, pex, erc} methods are callable at any tier, reading the netlist together with the incrementally-built GDS — no .gds dump required (Layout calls verify::drc(&self.netlist, Some(&self.gds)) and friends). Each returns a CheckReport (with is_clean() / findings() and a CheckKind). Today they return clean reports: the harness, report shape, and call sites are real, but there are no rule decks.

This is the load-bearing separation of duties: placement emits readiness witnesses (the RouterHandoffWitness, the gate verdicts, the degraded-confidence causes), while final DRC=0 and LVS=true belong to verification. A PlacementCertificate proves only facts owned by placement and checked by declared oracles — it is not a foundry-signoff substitute.

9. Roadmap to de-stub the placer

  1. Expose the bipartite device/net hypergraph from io::spice and feed it to the engine (core::run_flow notes where it plugs in).
  2. Compile a real CompiledPlacementTechnology and widen the stub's coverage classification to the full canonical Coverage enum.
  3. Replace run_placement with the real gate evaluator plus the typed oracles (drc / equivalence / access / routability), so gate verdicts become GateStatus::Pass on coded evidence instead of Degraded.
  4. Wire the hybrid solver (exact group packer + analytical centering) and group-preserving legalization so geometry flows into Layout and the incremental Gds.
  5. Add the Joint / ExternalOnly / ManualReview obligation classes (the missing three of the canonical seven) and a real IntentGraph.
  6. Land PEX / EM / LDE / thermal oracles, or declare them ExternalOnly coverage explicitly.
  7. Prove conflict-core minimality so an infeasible_core is a smallest unsatisfied set, not merely a preserved one.

Each step closes a row in crates/api/STUBS.md and removes a degraded-confidence marker — never a silently-ignored input. The certificate shape and the gate hierarchy do not change as the engine lands; only their contents graduate from stub to proven.
